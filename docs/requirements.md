# 要件定義

関連: [対象ユーザー](./target-users.md) · [設計判断](./design-decisions.md)

## 背景

小さな会社では、同じ質問が Slack や口頭で繰り返され、答える側の時間が見えない。ECHO は問い合わせを記録し、キーワードで束ね、対応時間と時給から損失と「先に書く1本」を出す。

## ゴール

1. 社内の1台で、全員が同じ集計を見られる
2. チャンネル（社内 / 社外）とテーマ（経費・VPN など）を分けて見られる
3. クラウドに本文を送らない
4. 日本語と英語の画面を切り替えられる（本文は翻訳しない）

## 機能要件

| ID | 内容 | 優先 |
| --- | --- | --- |
| F1 | 問い合わせを1件記録する（本文、チャンネル、質問者、回答者、対応分数） | Must |
| F2 | 本文入力中に、設定済みテーマ名・キーワードから候補を出す | Must |
| F3 | 貼り付け / CSV / JSON を追記する。置き換えは明示した場合のみ | Must |
| F4 | ダッシュボードで期間内の件数・時間・金額・テーマ数を出す | Must |
| F5 | テーマを件数順に並べ、行を選ぶと元メッセージを見る | Must |
| F6 | `#社内` / `#社外`（英語表示 `#internal` / `#external`）で集計を分ける。選択するとそのチャンネルの一覧が出る | Must |
| F7 | キーワードでテーマ分類する。一致しなければ未分類 | Must |
| F8 | テーマ・時給・期間・吸収率を設定し、保存後に再集計する | Must |
| F9 | UI を ja / en で切り替える。切替は localStorage | Must |
| F10 | `ECHO_ACCESS_PIN` があるときだけ PIN ゲート | Should |
| F11 | ブラウザに残った旧データを社内 JSON へ取り込む導線 | Should |
| F12 | 画面からの CSV 書き出し | Could（未実装。ファイルと `GET /api/workspace` で取得） |

## 非機能要件

| ID | 内容 |
| --- | --- |
| N1 | データは起動マシンの `data/workspace.json`。外部 SaaS に送らない |
| N2 | 同時書き込みはプロセス内の直列化（`withLock`） |
| N3 | サーバーレスでは永続化しない前提を README に書く |
| N4 | 実名データは Git に入れない（gitignore） |
| N5 | 損失計算の仮定（時給・吸収率）は設定で変える |

## 計算

- 時間（時間）= 対応分数合計 / 60
- 金額 = 時間 × 時給
- 年間換算 = 期間日数が正なら `365 / 期間日数`、0（全期間）なら 12
- 削減見込み = 年間 × 吸収率（未分類は 0）

## 画面

1. ダッシュボード — チャンネル、KPI、頻度、詳細、優先
2. 記録する — 1件フォーム、予測、一括取り込み
3. 設定 — 数値とテーマキーワード
4. PIN（任意）

## 対象外

- Slack / Teams の API 連携
- ベクトル類似度による自動クラスタ
- マルチテナント・ユーザーアカウント
- スマホ専用アプリ
